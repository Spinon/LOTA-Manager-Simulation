// moba_manager_ai_design_codex.txt
// Documento de arquitetura de IA para um simulador de manager de MOBA.
// Objetivo: criar uma IA interessante, legível e expansível, não apenas uma coleção de fórmulas.
// Linguagem-alvo sugerida: TypeScript.
//
// Ideia central:
// A IA não deve jogar como um bot perfeito. Ela deve simular jogadores e times com estilo, leitura de mapa,
// disciplina, erro, comunicação, tilt, conforto de herói, plano de draft e adaptação ao estado da partida.

================================================================================
1. FILOSOFIA DA IA
================================================================================

O manager precisa de uma IA que responda a quatro perguntas:

1. O que o time quer fazer?
2. O que cada jogador acha que deve fazer?
3. O que cada jogador consegue executar?
4. O que realmente acontece na partida?

A diferença entre essas quatro respostas cria a graça do manager.

Exemplo:

O time quer fazer Roshan.
O carry quer terminar um item.
O suporte acha que precisa wardar antes.
O mid está sem ultimate.
O offlaner está confiante demais e entra antes.

Resultado:
A jogada pode atrasar, falhar, virar fight ruim, ou funcionar porque o adversário errou mais.

A IA deve ter:
- intenção macro;
- personalidade de jogador;
- incerteza de informação;
- execução imperfeita;
- comunicação;
- adaptação durante a partida;
- memória curta;
- estilo de time.

================================================================================
2. CAMADAS DA IA
================================================================================

Criar a IA em camadas:

1. GameStateAnalyzer
   Lê o estado bruto da partida e produz métricas úteis.

2. TeamBrain
   Decide o plano macro do time.

3. PlayerAgent
   Cada jogador/herói decide seu modo atual.

4. RoleBrain
   Ajusta prioridades conforme posição 1-5.

5. TacticalPlanner
   Transforma o plano em ações coordenadas.

6. ActionSelector
   Escolhe ação concreta.

7. ExecutionModel
   Aplica erro humano, delay, mecânica, comunicação e fadiga.

8. MemorySystem
   Guarda eventos recentes e tendências.

9. AdaptationSystem
   Ajusta pesos conforme a partida evolui.

10. PersonalitySystem
   Faz jogadores diferentes tomarem decisões diferentes.

================================================================================
14. MODELO DE EXECUÇÃO HUMANA
================================================================================

A decisão pode ser boa, mas a execução pode falhar.

executionSuccessChance =
  baseActionReliability
  + relevantPlayerSkill
  + heroMastery
  + teamCommunication
  + moraleModifier
  - actionDifficulty
  - fatiguePenalty
  - tiltPenalty
  - pressurePenalty

executionSuccessChance =
  clamp(executionSuccessChance, 0.05, 0.98)

Se falhar:

failureType =
  weightedRandom([
    late_reaction,
    bad_position,
    missed_spell,
    wrong_target,
    panic_retreat,
    overcommit,
    no_followup,
    mechanical_error
  ])

Impacto por falha:
- late_reaction: ação ocorre com delay.
- bad_position: aumenta risco.
- missed_spell: spell entra em cooldown e não aplica efeito.
- wrong_target: aplica ação em alvo subótimo.
- panic_retreat: cancela plano.
- overcommit: aumenta chance de morte.
- no_followup: reduz valor de iniciação.

================================================================================
15. COMUNICAÇÃO DO TIME
================================================================================

Mesmo que TeamBrain escolha um plano, jogadores podem não seguir.

followCallChance =
  teamCoordination
  * playerObedienceToCalls
  * playerCommunication
  * planClarity
  * moraleMultiplier
  * (1 - tiltPenalty)

Se não segue call:
  player usa modo individual com menor teamPlanModifier.

Call clarity:

planClarity =
  confidence
  + visionInformation
  + obviousObjectiveValue
  - chaosLevel

Chaos level:

chaosLevel =
  multipleThreats
  + recentDeaths
  + conflictingLanePressure
  + lowVision
  + teamTilt

estimatedEnemyPosition =
  lastSeenPosition

  timeSinceLastSeen
  * enemyMobility
  * mapDarkness

threatFromMissingEnemy =
  enemyGankPower
  * uncertaintyWeight
  * proximityToLikelyPath

Se time tem alta mapAwareness:
  reduz uncertainty.

Se time tem visão boa:
  reduz uncertainty.

================================================================================
17. PERSONALIDADE E ERROS INTERESSANTES
================================================================================

Jogador agressivo:
  fightScore += aggression * 0.2
  finishEnemyScore += aggression * 0.3
  retreatScore -= aggression * 0.15

Jogador disciplinado:
  retreatScore += discipline * 0.15 quando risco alto
  highGroundThrowRisk pesa mais
  randomNoise menor

Jogador ganancioso:
  farmScore += greed * 0.25
  joinFightScore -= greed * 0.10 se itemTiming próximo
  deathRisk ignorado parcialmente

Jogador playmaker:
  gankScore += playmakingBias * 0.25
  initiationScore += playmakingBias * 0.25
  overcommitRisk += se discipline baixo

Jogador suporte protetor:
  saveAllyScore += saveAllyBias * 0.30
  wardScore += visionDiscipline * 0.20

================================================================================
18. TILT E MOMENTUM
================================================================================

tiltGain =
  deathValue
  + throwEvent
  + blameEvent
  + losingStreak
  - tiltResistance

tiltRecovery =
  goodFight
  + coachPause
  + objectiveTaken
  + timeWithoutMistake

tiltLevel =
  clamp(tiltLevel + tiltGain - tiltRecovery, 0, 100)

Efeitos:

executionSuccessChance -= tiltLevel * 0.002
randomNoise += tiltLevel * 0.1
disciplineEffective -= tiltLevel * 0.3
aggressionEffective += tiltLevel * tiltAggressionBias

if personality.tiltResponse == "passive":
  aggressionEffective -= tiltLevel * 0.2
  retreatScore += tiltLevel * 0.2

if personality.tiltResponse == "reckless":
  aggressionEffective += tiltLevel * 0.2
  retreatScore -= tiltLevel * 0.2

20. ROLE BRAIN
================================================================================

Position 1 Carry:
  prioriza farm, item timing, segurança, late game.
  entra em fight quando ultimate/item pronto, fight é perto, objetivo alto ou time precisa dele.

Position 2 Mid:
  prioriza runas, tempo, gank, burst, controle de mapa.
  alterna entre farm e playmaking.

Position 3 Offlane:
  prioriza pressão, iniciar, ocupar área perigosa, quebrar mapa.
  aceita mais risco.

Position 4 Soft Support:
  prioriza rotação, runa, gank, visão agressiva, setup.
  cria caos.

Position 5 Hard Support:
  prioriza proteção, visão defensiva, save, pulls, stacks.
  sacrifica recursos.

export function updateTeamAi(input: {
  rawGameState: RawGameState;
  teamProfile: TeamAiProfile;
  playerProfiles: PlayerAiProfile[];
  currentTeamMemory: TeamMemory;
  previousTeamPlan?: TeamPlan;
  deltaTime: number;
}): TeamAiOutput {
  const analyzed = analyzeGameState(input.rawGameState);

  const memory = updateTeamMemory(
    input.currentTeamMemory,
    input.rawGameState.recentEvents,
    input.deltaTime
  );

  const candidatePlans = generateTeamPlans({
    analyzed,
    teamProfile: input.teamProfile,
    memory,
  });

  const teamPlan = selectTeamPlan({
    candidatePlans,
    previousPlan: input.previousTeamPlan,
    teamProfile: input.teamProfile,
  });

  const playerOutputs = input.playerProfiles.map((playerProfile) => {
    const context = buildPlayerContext({
      analyzed,
      teamPlan,
      playerProfile,
      memory,
    });

    const modeScores = scorePlayerModes(context);

    const selectedMode = selectPlayerMode({
      modeScores,
      previousMode: input.rawGameState.players[playerProfile.playerId].currentMode,
      playerProfile,
    });

    const candidateActions = generateActionsForMode({
      mode: selectedMode,
      context,
    });

    const selectedAction = selectAction({
      candidateActions,
      context,
    });

    const executedAction = applyExecutionModel({
      action: selectedAction,
      context,
      playerProfile,
    });

    return {
      playerId: playerProfile.playerId,
      selectedMode,
      selectedAction,
      executedAction,
      modeScores,
    };
  });

  return {
    analyzed,
    memory,
    teamPlan,
    playerOutputs,
  };
}

export function scoreRetreatMode(ctx: PlayerContext): PlayerModeScore {
  const score =
    ctx.self.lowHealthScore
    + ctx.self.incomingDamageThreat
    + ctx.local.enemyNumbersAdvantage * 12
    + ctx.map.missingEnemyThreat * 8
    + ctx.self.keySpellsOnCooldownPenalty
    - ctx.local.nearbyAlliedSave * 10
    - ctx.local.towerSafety * 8
    - ctx.profile.personality.riskTolerance * 0.15;

  return {
    mode: "retreat",
    score,
    urgency: Math.min(100, score),
    risk: 100 - score,
    reasonTags: ["health", "threat", "numbers", "safety"],
  };
}

export function scoreFarmLaneMode(ctx: PlayerContext): PlayerModeScore {
  const score =
    ctx.map.safeLaneFarmValue
    + ctx.hero.itemTimingUrgency * 0.8
    + ctx.role.farmPriority * 10
    + ctx.profile.personality.farmBias * 0.2
    - ctx.map.gankRisk * 1.2
    - ctx.teamPlan.fightUrgency * 0.8;

  return {
    mode: "farm_lane",
    score,
    urgency: ctx.hero.itemTimingUrgency,
    risk: ctx.map.gankRisk,
    reasonTags: ["farm", "item_timing", "lane"],
  };
}

export function scoreJoinFightMode(ctx: PlayerContext): PlayerModeScore {
  const score =
    ctx.fight.nearbyFightValue
    + ctx.teamPlan.fightUrgency
    + ctx.hero.fightReadiness
    + ctx.local.numbersNeeded * 10
    + ctx.self.teleportAvailableValue
    - ctx.hero.itemTimingConflict
    - ctx.self.lowResourcePenalty;

  return {
    mode: "join_fight",
    score,
    urgency: ctx.teamPlan.fightUrgency,
    risk: ctx.fight.fightRisk,
    reasonTags: ["fight", "team_plan", "cooldowns"],
  };
}

export function applyExecutionModel(input: {
  action: BotAction;
  context: PlayerContext;
  playerProfile: PlayerAiProfile;
}): ExecutedAction {
  const skill =
    getRelevantSkillForAction(input.action.type, input.playerProfile);

  const successChance = clamp(
    input.action.expectedValue / 100
      + skill / 100
      + input.playerProfile.heroMastery / 200
      + input.context.team.coordination / 200
      - input.action.risk / 150
      - input.context.player.fatigue / 200
      - input.playerProfile.personality.tiltLevel / 200,
    0.05,
    0.98
  );

  const roll = random();

  if (roll <= successChance) {
    return {
      ...input.action,
      executed: true,
      failureType: null,
      delaySeconds: 0,
    };
  }

  const failureType = chooseFailureType(input.action, input.context, input.playerProfile);

  return {
    ...input.action,
    executed: false,
    failureType,
    delaySeconds: failureType === "late_reaction" ? randomBetween(0.3, 1.5) : 0,
  };
}

38. RESUMO PARA O CODEX
================================================================================

Construir uma IA de manager baseada em Utility AI com camadas:

GameStateAnalyzer:
  transforma estado bruto em análise.

TeamBrain:
  escolhe plano macro com base em estilo, visão, objetivos, timings e risco.

PlayerAgent:
  escolhe modo individual ponderado por role, personalidade, skill, plano do time e memória.

ActionSelector:
  escolhe ação concreta dentro do modo.

ExecutionModel:
  aplica erro humano, delay, falha mecânica, tilt e fadiga.

MemorySystem:
  faz a IA lembrar eventos recentes e adaptar pesos.

A IA não deve ser perfeita.
Ela deve ser crível, configurável, testável e divertida para um manager.
